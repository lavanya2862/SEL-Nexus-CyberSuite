# Attack Detection Agent Split: Database Table Ownership

This document categorises every table in `data/threat_intel.duckdb` (defined in `threat_intel/store.py`) to prepare for separating the Attack Detection Agent into its own folder and data store (`agents/attack_detection`).

### Classification Rule
- **Attack Detection**: Used only by `hunting/`, `correlate.py`, `resolve.py`, `attack_report.py`, or `Pipeline.attack_check()`.
- **Threat Intel**: Used only by Threat Intel collection, derivation, analysis, scoring, and reporting.
- **Fix engine**: Used specifically for device settings and remediation planning.
- **Shared**: Used by both Threat Intel and Attack Detection (or Fix engine); annotated with who writes and who reads.

### Separation Summary for Phase 3

When the Attack Detection Agent is moved to `agents/attack_detection`:
1. **Tables that move exclusively to Attack Detection**:
   - `hunts`
   - `hunt_results`
   - `resolutions`
2. **Tables that remain exclusively in Threat Intel**:
   - `feed_state`, `cves`, `iocs`, `software`, `device_vulns`, `defender_seen`, `analysis`, `reports`, `threat_fixes`
3. **Table that belongs to the Fix engine**:
   - `device_settings`
4. **Tables that need contract-based decoupling (currently Shared)**:
   - `threats` & `threat_links`: Attack Detection will read threats and indicators from Threat Intel's published output (`threat_intel/data/out/iocs.json`), avoiding direct database queries.
   - `devices`: Attack Detection will consume inventory data from Threat Intel or query Defender directly.
   - `exposure`: Handled entirely within Threat Intel once `correlate.py` moves to Attack Detection and focuses only on hunt hits.
   - `findings`: Once split, Attack Detection owns attack findings (`findings.json`), and Threat Intel tracks exposure matches independently via `exposure.py`.
   - `scores`: Threat Intel owns threat scoring; Attack Detection publishes findings that feed into subsequent Threat Intel runs.
   - `runs`, `alerts`, `ai_usage`: Each agent maintains its own run state, alerts, and AI rate limiter / usage tracking.
